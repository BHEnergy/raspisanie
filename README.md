# Ритм · недельный планировщик

Vue 3, Composition API (`script setup`) и Vite. Адаптивный интерфейс на русском языке без сервера.

## Запуск

Node.js 22.12+ или 24.

```sh
npm install
npm run dev
```

`npm run build` — сборка в `dist`, `npm run preview` — просмотр сборки, `npm test` — тесты календаря и сохранений.

## Возможности

- Шесть карточек: понедельник–суббота с актуальными датами.
- Добавление, редактирование, удаление, выполнение, важность, перенос задачи на следующий день.
- Необязательное время задачи (часы и минуты) в редакторе и карточке; сохраняется для повторов. Это время в плане, без системных уведомлений.
- Перетаскивание за ручку ⋮⋮ меняет порядок и день задачи, в том числе на сенсорном экране. На ручке доступны Alt + вверх/вниз для порядка и Alt + влево/вправо для дня.
- Плавные переходы окон, отметок, кнопок и перемещений учитывают системную настройку уменьшения движения.
- Собственные категории с названием и цветом, поиск и фильтры.
- Заметки «Со вчера», «На завтра», «Не забыть» для каждого дня. Заметки — свободный текст; перенос задачи выполняется отдельной стрелкой.
- Еженедельные повторы: настройка в редакторе задачи. Повтор появляется в выбранный день следующей недели с пустой отметкой выполнения.
- В воскресенье в 00:00 по местному времени браузера начинается планирование следующего понедельника. Текущая неделя архивируется, новые карточки заполняются датами и повторяющимися задачами. Разовые задачи остаются в архиве.
- Архив доступен для чтения, экспорт и восстановление JSON-копии.

Обновление недели проверяется при запуске, возврате в окно и каждые 30 секунд. Закрытая статическая страница не выполняет код: после открытия приложение сразу обновит неделю. При длительном отсутствии архивируется последняя сохранённая неделя; пустые пропущенные недели не создаются.

Данные хранятся в localStorage конкретного браузера и адреса сайта, не отправляются в GitHub, не синхронизируются между устройствами. Очистка браузера удалит данные — используйте экспорт. Категории сохраняются при смене недели. Интерфейс использует системные шрифты без внешних запросов.

## GitHub Pages

### Индексация и иконка

В `index.html` установлена директива `noindex, nofollow, noarchive`. `public/robots.txt` разрешает обход: это нужно, чтобы поисковик прочитал `noindex`. Запрет обхода через `Disallow` сам по себе не гарантирует исключение URL из поиска. На GitHub Pages в подпапке репозитория robots.txt не управляет всем доменом; метатег работает непосредственно на странице. Это ограничение для поисковых систем, не пароль или ограничение доступа к сайту. SVG favicon находится в `public/favicon.svg` и подключён с учётом относительного пути сборки.

Загрузите проект в свой репозиторий с основной веткой `main`. В Settings → Pages → Build and deployment выберите **GitHub Actions**. Включён workflow `.github/workflows/deploy.yml`: тесты, сборка и публикация при push в `main`. Если ветка другая, измените `branches` в workflow. Vite использует относительные пути (`base: './'`), поэтому приложение работает и в подпапке репозитория.

Проект подготовлен по [руководству Vite для GitHub Pages](https://vite.dev/guide/static-deploy#github-pages). Реализация Vue использует [Composition API и script setup](https://vuejs.org/api/sfc-script-setup.html).
